# Bizar Harness

Use `/bizar` to orient a task to the installed Claude Code-native harness.

1. Read the repository instructions and inspect durable state with `ok task list`, `ok plan list`, and `ok prd list`.
2. After bounded orientation, work directly when one capable owner fits. Delegate only for a real capability gap, independent review, context isolation, or disjoint parallel scope.
3. Ask one concise clarification question only when orientation leaves a material outcome, acceptance criterion, constraint, or safety boundary unresolved. Otherwise proceed autonomously.
4. State the target result, constraints, validation evidence, and stop condition.
5. Use `bizar --help` for CLI primitives and the installed skills for workflow-specific instructions.
6. Treat impact as evidence/rollback metadata. Honor only explicit operator restrictions; do not add Bizar approval gates.

OpenKan is Bizar’s default durable planning, progression, and PRD-goal surface under `.ok/`; Bizar ships it through `bizar openkan`, `ok task`, `ok plan`, and `ok prd`. Project files, Claude Code hooks, MCP tools, and CLI output remain the orchestration surfaces.
